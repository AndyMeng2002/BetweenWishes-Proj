# 从零开始：直接使用新 GitHub 账号上线「心愿之间」💗

这份 ZIP **已经是完整代码项目**，不需要旧 GitHub 仓库。
你不需要自行购买服务器，我们采用：

- **GitHub**：保存你的项目源代码
- **Supabase**：数据库、注册登录、照片存储、少量后台函数
- **Vercel**：在互联网上运行你的网页

> 必须先测试，再邀请真实客户使用。
> 本文件中的账号密码、密钥都由你自行填写，不需要发给别人。

---

## 第一步：上传到你的新 GitHub 账号

**特别注意：GitHub 需要的是解压后的源代码文件，不是把 ZIP 本身作为一个文件放进仓库。**

1. 下载并**解压** `BetweenWishes_可直接上传GitHub_完整项目.zip`。
2. 找到解压后的文件，其中应直接有 `package.json`、`index.html`、`src`、`public`、`supabase` 等。
3. 登录 https://github.com ，右上角 `+` → `New repository`。
4. Repository name 填 `between-wishes`，初期建议选择 **Private**。
5. 点击 `Create repository`。
6. 在新仓库页面选择 `uploading an existing file`（或 Add file → Upload files）。
7. 把**解压后的项目内容**拖进上传区域，包括 `src`、`public`、`supabase` 等文件夹，以及项目根目录文件。
8. 提交时填写 `Initial website source`，点击 `Commit changes`。
9. 检查仓库根目录直接能看到 `package.json`，而不是只看到一个 ZIP 文件。

如果网页上传文件夹不方便，也可以用 **GitHub Desktop**：
File → Add Local Repository → 选择解压后的文件夹 → 若提示非仓库则创建仓库 → Publish repository。
确保发布前选择自己想要的可见性。

**不要上传 `.env.local`、数据库密码、Service Role / Secret Key。**

## 第二步：创建 Supabase 项目（数据库+账号系统）

1. 打开 https://supabase.com/dashboard ，注册/登录。
2. 点击 `New project`。
3. 项目名字建议 `between-wishes-dev`。
4. 数据库密码自己保管，不要发到聊天或放入 GitHub。
5. 等项目创建完成。
6. 左侧进入 `SQL Editor` → `New query`。
7. 打开本项目 `supabase/migrations/20261025_001_initial.sql`，复制全部内容。
8. 确认这是全新的**空数据库项目**，点击 `Run`。**只能执行一次**。
9. 回到 `Table Editor`，确认有六张表：
   `profiles` / `binding_requests` / `couples` / `wishes` /
   `gift_records` / `notifications`。
10. 进入 `Storage`，应该看到**私有**的 `wish-images` Bucket。
11. 可以用 `supabase/verify_schema.sql` 检查结构（这个文件只读，不会删除数据）。

⚠️ 如果你在同一个 Supabase 项目里运行过旧版初始化 SQL，
**不要再运行本文件**；应新建一个空的测试 Supabase 项目，最简单也最安全。

## 第三步：取得你的两个项目配置值

在 Supabase → `Connect` 或 `Project Settings → API Keys` 找到：

- `Project URL`：形如 `https://xxxx.supabase.co`
- `Publishable Key`：形如 `sb_publishable_...`

这两个是浏览器可以使用的连接信息，配合数据库 RLS 权限工作。

**这些绝对不能放入前端：** 数据库密码、`service_role`、`sb_secret_*`、Supabase 个人 Access Token。

## 第四步：用 Vercel 部署网站

1. 打开 https://vercel.com/dashboard ，注册/登录。
2. `Add New` → `Project` → 连接并导入你刚建立的 **新 GitHub 仓库**。
3. Framework Preset 选择 `Vite`（通常自动识别）。
4. 添加以下 **Environment Variables**：

   `VITE_SUPABASE_URL` = 第二步获得的 Project URL

   `VITE_SUPABASE_PUBLISHABLE_KEY` = 第三步获得的 Publishable Key

5. 点击 `Deploy`。
6. 部署成功后会得到一个网址（例如 `https://between-wishes-xxx.vercel.app`）。
7. 之后更改环境变量请记得 `Redeploy`。

构建参数通常自动识别；需要手动填写时：
- Build Command：`npm run build`
- Output Directory：`dist`
- Install Command：`npm install`

## 第五步：设置邮件登录的跳转地址

在 Supabase → `Authentication` → `URL Configuration`：

- `Site URL`：填写**你实际得到的 Vercel 网址**，不能照抄例子
- `Redirect URLs`：新增 `http://localhost:3000/**`
- 再增加 `https://你实际的网站域名/**`

这样注册验证邮件、找回密码邮件才会正确返回你自己的网站。

在 Authentication → Providers / Email 确认邮箱注册已打开，
最好开启邮箱确认，避免别人冒用邮箱。

## 第六步：部署“删除账号”后台函数

这是单独的一步，不能只靠上传 React 前端就完成：

1. Supabase → Edge Functions → 创建名为 `delete-account` 的函数。
2. 从项目文件 `supabase/functions/delete-account/index.ts` 复制全部源码。
3. **保持 JWT 验证开启**，不要允许匿名调用。
4. 发布后，使用专用测试账号检查账号删除。
5. 永远不要把服务端 `service_role` 或 `secret` 复制到 Vercel 的 `VITE_*` 变量中。

若使用 Supabase CLI，项目已附 `supabase/config.toml`。

## 第七步：上线前必须做的测试

准备两个**不同邮箱**、两个**不同浏览器或手机**，按顺序检查：

- [ ] A 注册账号并完成邮箱验证。
- [ ] B 注册账号；B 无法读取 A 的心愿。
- [ ] A 添加心愿、上传图片。
- [ ] A 退出并换设备重新登录，心愿仍在。
- [ ] A 输入 B 的用户名发邀请。
- [ ] B 接受邀请，两边都看到绑定关系。
- [ ] B 抽选 A 的心愿，可以看到抽中的详情和相应图片。
- [ ] A 在送礼前不能看到 B 的抽选结果或购买状态。
- [ ] B 标记已购买，A 仍看不到购买状态。
- [ ] B 确认送出后，A 才能看到礼物和通知。
- [ ] A 归档心愿时，不会显示“已经被抽中”。
- [ ] 账号删除、解绑、数据导出、邮箱找回密码均按预期工作。

**还需要做数据库级权限测试**：直接用 A、B 两个账号令牌请求 Supabase API，
检查跨用户越权读取/更新确实被 RLS 阻止。只点页面是不够的。

## 第八步：对外开放给真实客户前

- 配置自定义 SMTP 邮件服务，不要依赖 Supabase 默认测试邮件额度。
- 填完 `public/privacy.html`、`public/terms.html` 的所有占位符，
  按真实经营主体/适用法律进行必要审核。
- 检查 Supabase 项目的备份选项、实际演练恢复流程。
- 配置基础监控、错误通知、联系邮箱与故障回滚方案。
- 检查数据库和 Storage 的用量及费用限制。
- 先小范围邀请真实测试者，确认数据和权限安全，再正式开放。
